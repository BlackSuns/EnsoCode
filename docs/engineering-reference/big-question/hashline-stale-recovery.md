# Hashline 过期快照恢复不能退化成猜行号

## 症状

文件远处插入、删除或修改后，旧 TAG 的 PUT 被直接拒绝，即使目标区域没有变化。
取消 TAG 校验或直接复用旧行号则可能覆盖错误位置。

## 根因

TAG 描述全文件版本，PUT 使用该版本的行号。全文件变动不等于目标冲突，但必须重新证明目标位置。

只取 diff 的某个对齐结果无法排除重复块歧义。仅要求新文件中的目标唯一也不够：旧快照有两份相同窗口、新文件只剩一份时，不能判断留下的是哪份。

归一化不能改变坐标系：`a\n ` 的末行是没有终止换行的空白行；先整文去尾空白再切行，会把它误当作 `a\n` 的终止符并丢掉。恢复比较必须先按原文切可寻址行，再逐行归一。

## 修法

- 先按旧快照校验 PUT 的语法、正文、范围和重叠，不用新文件长度挽救非法旧坐标。
- 目标范围上下各取三行上下文，重叠窗口合并。窗口在旧快照和当前文件中都必须唯一匹配。
- 比较仅复用既有行尾空白归一规则；因此目标区域仅有行尾空白变化时仍可能恢复。BOM 不参与行内容比较。实际修改仍基于当前文件，保留 BOM 和未修改行的原始换行。
- 多组窗口允许不同位移，但必须保持顺序，迁移后的 PUT 不得重叠。任一组失败，整份补丁不写入。
- 旧快照、当前文件各限 2 MiB、50,000 行；整份补丁共享 2,000,000 次行比较预算。超限、缺快照、冲突或歧义均拒绝并要求重新读取。
- 写前再次读取并比较原始文本，变化则拒绝，不自动重试。会话工具链路成功后返回新 TAG、迁移范围和末尾提示。

## 保证边界

这是保守的文本定位，不是语义合并。目标附近三行发生变化也可能要求重新读取；旧块被删除、别处新增一份包含相同上下文的块，单靠文本快照无法证明语义身份。

写前复核只缩小并发窗口，不是原子 CAS，不保证外部进程不会在复核与写入之间再次修改文件。

恢复依赖同一 path 下 TAG 能确定旧快照文本；16 位 TAG 碰撞可能令基线错误，本方案不提供碰撞下的定位安全保证。短 TAG 的碰撞机制、快照持久化及全局写队列不由这次恢复处理。
